# Sprint 1 Retrospective

## Terminology

- **Sprint Retrospective:** The last event within the Sprint. The Scrum Team
  inspects individuals, interactions, processes, tools, and the Definition of
  Done, then identifies improvements for the next Sprint.
- **Sprint Backlog:** The Sprint Goal, selected Product Backlog items, and the
  actionable plan for delivering the Increment.
- **Definition of Done:** The required quality conditions an Increment must
  satisfy before it is treated as complete.

## What went well

- The team considered the development tempo good. Record participant votes or
  supporting evidence if this point will be assessed.
- Using the OpenAI API made the AI-enabled work easier.
- Docker improved development consistency.

## What changed from initial planning

- The team included OpenAI API calls in integration tests.
- The testing approach shifted toward integration tests with fewer mocks after
  discussion of DHH podcasts.
- The team reported that the AI-integrated tests used approximately $0.01 of
  OpenAI API credit. Billing evidence is not included in the source notes.
- The workflow changed so users cannot begin coding until the AI approves their
  problem understanding and functional approach.
- The team observed that users should verify both the problem and their
  approach before coding, even when they feel confident.

## Problems identified

- The problem set is limited.
- The integrated code editor needs visual and usability improvements.
- The AI Socratic chat interface needs visual and usability improvements.
